# Working on Baselane mods

Claude Code mods: plugins of function hooks (Claude Code 2.1.288, early-access API).

## Layout

- `engines/<engine>/engine.json`: the engine's shared files and how a mod wires its rules (see `scripts/build.mjs`).
- `engines/<engine>/hooks/engine.ts`: the engine. `hooks/rules/<id>.ts`: one rule per file.
- `engines/<engine>/tests/`: shared test helpers and one `<id>.test.ts` per rule.
- `catalog/<name>.json`: `{ "engine", "mods": [{ "name", "description", "rules": [ids] }] }`. A mod with several rules is a pack.
- `plugins/`: GENERATED by `node scripts/build.mjs`. Never edit it by hand.

## Check before you report

`bash scripts/check.sh` rebuilds, then runs `claude plugin validate`, `claude plugin test` and a type check on every mod and engine. Pass mod names to check only those. A change is done only when it prints `check: 0 failure(s)`.

Prove each test can fail: break a copy of the rule in a scratch folder and confirm a test fails.

## API facts that are not obvious

The types file is the authority. Its path is in `scripts/check.sh` (`TYPES`). Grep it for the event or noun at hand.

- A hook is `($, e, next)`. `next(e)` continues; returning without `next` answers for the rest.
- Never pass `$` as an argument, store it or return it: the module then fails to load. Call `$.noun.method()` at the call site, or pass closures that do.
- `tool.call` answers only `{ deny }` or `{ result }`. To ask the person, use `classic.PreToolUse` returning `{ ask }`. Its `e` is `{ tool, tool_use_id, ...args }`.
- `$.process.run(argv, init)`: argv array first. Output caps at 4 MiB (`isStdoutTruncated`); a timeout rejects.
- `$.session.cwd()`, `$.session.usage()` (`context.percent`, `cost`), `$.ui.toast(text)`, `$.ui.status(text)`, `$.ui.log(text)`.
- Panes: `$.ui.open({ id, title })` plus a `ui.render` hook on `{ component: 'Pane', requestId: id }`. Elements come from `$.ui.resolve(e)` (no element globals). State a drawing reads lives in `$.state` (declare it in the mod's `types/index.d.ts` under `interface PluginState`), not module variables. A render hook never writes state.
- Slash commands: `$.command.register({ name, description })` in `session.start`, answered by `on('command.run', { command: name }, ...)` returning `{ text }`.
- In `claude plugin test`: the test's own `on` hooks sit beneath the plugin and stand for the engine. A hook for a `$` call returns `{ value: X }` (for example `on('session.cwd', () => ({ value: '/repo' }))`). The test must answer `classic.Stop` itself (`() => ({})`). A test sees an ask indirectly: its own `classic.PreToolUse` hook is not reached and the tool still runs.
- Test inputs to a rule need `tool_use_id`.

## Style

Match the existing engines: small files, no mutation of inputs, comments only where the why is not obvious, no em-dashes in any text.
